# FairSky: работа без консольных команд

Откройте папку этой рабочей копии FairSky в **настольном VS Code для Windows**.
В левом нижнем углу должна быть ветка `feature/dock-cards-b`.

## Однократная настройка

1. Откройте Extensions (`Ctrl+Shift+X`). Официальное расширение **GitHub Pull Requests** (`GitHub.vscode-pull-request-github`) установлено на этом компьютере; для других компьютеров оно добавлено в рекомендации проекта.
2. Откройте значок GitHub слева и выберите **Sign In**. Подтвердите вход в браузере под `zoeyrus`. Этот личный вход пользователь выполняет самостоятельно.
3. Для проверки сборки нажмите `Ctrl+Shift+B`: задача **FairSky: Build Debug x64** уже настроена.
4. Для автоматических проверок откройте **Terminal → Run Task → FairSky: Check Dock**. Вводить команды вручную не нужно.

## Обычный цикл

1. Откройте Source Control (`Ctrl+Shift+G`). Нажмите файл, чтобы посмотреть изменения.
2. Нажмите `+` у нужных файлов (**Stage Changes**).
3. Напишите описание и нажмите **Commit**.
4. Нажмите **Publish Branch** для новой ветки или **Push** в меню `…` для опубликованной.
5. В панели GitHub Pull Requests выберите **Create Pull Request**. Базовая ветка — `main`, исходная — ваша рабочая ветка. Пока проверка интерфейса не завершена, используйте **Create Draft**.
6. Проверяйте изменённые файлы и обсуждение прямо в панели PR. Объединяйте только после проверки в Command Palette.

Не выполняйте Discard All Changes в старой рабочей копии: она отдельно сохранена в Documents/Projects/Dockprojects/FairSky. Не работайте одновременно с двумя копиями, не проверив путь открытой папки.

## Коннектор GitHub в чате

Доступ к `zoeyrus/fairsky-cmdpal` проверен чтением PR #2 и исходников `main`. Можно попросить проверить PR, прочитать изменения, подготовить PR или посмотреть результаты GitHub Actions. Коннектор работает с удалённым GitHub; он не заменяет личную авторизацию VS Code и не устанавливает MSIX в Windows.

При проверке создание PR через коннектор вернуло `403: Resource not accessible by integration`: права на чтение есть, запись через это подключение ограничена. Для создания PR используйте установленное расширение VS Code. Настройка подключения GitHub должна отдельно разрешать запись Pull Requests; вход в VS Code сам по себе права коннектора не меняет.

Пример: «Проверь изменения в PR и результаты проверок, но пока не объединяй».

Документация: https://code.visualstudio.com/docs/sourcecontrol/github
